# 创世纪 · 剧本连贯性锚点系统

## 核心理念：锚点驱动生成

剧本生成采用**锚点驱动**模式，确保每一个场景、每一个章节都严格基于已建立的全局锚点进行创作，杜绝脱节、跳章、重复等问题。

## 一、全局锚点体系（World Bible）

### 1.1 角色锚点（Canonical Characters）

每个角色必须有唯一身份标识，后续生成只能引用已建立的角色：

```json
{
  "characters": [
    {
      "id": "char_001",
      "name": "角色姓名",
      "basicInfo": "性别、年龄、外貌、身份",
      "traits": ["核心性格标签1", "核心性格标签2"],
      "relationships": [
        { "targetId": "char_002", "relation": "关系描述" }
      ],
      "speechStyle": "语言风格描述",
      "catchphrase": "标志性台词/口头禅"
    }
  ]
}
```

**强制规则：**
- 角色名必须与小说原文一致
- 新角色出场必须在原文中有明确描述
- 同一角色的外貌、性格、语言风格必须前后一致
- 角色之间的关系不得与原文矛盾

### 1.2 世界观锚点（World Context）

```json
{
  "worldContext": {
    "era": "时代背景",
    "locations": [
      { "id": "loc_001", "name": "地点名", "description": "详细描述" }
    ],
    "timeFlow": "时间流逝规则",
    "culturalBackground": "文化背景"
  }
}
```

**强制规则：**
- 地点必须是真实存在的，不得随意编造
- 地点转换必须有合理的过渡说明
- 时间线必须线性推进，不得倒叙（除非明确标注闪回）

### 1.3 剧情锚点（Plot Anchors）

```json
{
  "plotAnchors": {
    "mainPlot": "主线剧情描述",
    "currentStage": "当前剧情阶段",
    "pendingThreads": ["未解决的线索/悬念"],
    "resolvedThreads": ["已解决的线索"],
    "characterArcs": [
      { "charId": "char_001", "currentState": "当前状态", "targetState": "目标状态" }
    ]
  }
}
```

## 二、角色状态账本（Character State Ledger）

### 2.1 状态追踪维度

每个角色在每个章节结束时必须记录完整的状态：

```json
{
  "stateLedger": {
    "chapterIndex": 5,
    "characters": {
      "char_001": {
        "emotionalState": "当前情绪（如：愤怒、悲伤、平静）",
        "physicalState": "身体状况（如：受伤、健康、疲惫）",
        "location": "当前位置",
        "possessions": ["持有物品列表"],
        "activeActions": ["正在进行的行动"],
        "pendingDecisions": ["待做出的决定"],
        "lastDialogue": "上一场最后的台词",
        "lastAction": "上一场最后的动作"
      }
    }
  }
}
```

### 2.2 状态转移规则

**章节间状态必须连续：**
1. 上一章结尾的状态 = 下一章开头的起始状态
2. 状态变化必须有明确的触发事件
3. 禁止凭空改变状态（如：上一章受伤，下一章突然痊愈且无交代）

**场景间状态必须连续：**
1. 每个场景结束时必须更新角色状态
2. 下一个场景开始时必须以上一场的状态为起点
3. 状态变化必须通过 action/dialogue 体现

## 三、场景连贯性生成规则

### 3.1 场景三要素

每个场景必须包含：

1. **入场锚点**：基于上一场结尾的状态
   - 角色从哪里来（location延续）
   - 角色当前情绪/身体状态（emotionalState/physicalState延续）
   - 延续上一场的未完成行动（activeActions延续）

2. **场景任务**：必须完成一个新的剧情任务
   - 推进主线剧情
   - 解决/制造冲突
   - 推进角色弧线
   - 揭示/隐藏信息

3. **出场锚点**：为下一场提供明确的起点
   - 角色新状态（更新emotionalState/physicalState）
   - 新位置或保持当前位置
   - 新的未完成行动（为下一场铺垫）
   - 悬念或钩子

### 3.2 场景衔接检查清单

生成每个场景时必须自检：

- [ ] 是否明确承接上一场的角色位置？
- [ ] 是否延续上一场的角色情绪/身体状态？
- [ ] 是否从上一场的最后一个动作/对白自然过渡？
- [ ] 是否有明确的新剧情任务（不是重复上一场）？
- [ ] 是否为下一场留下了清晰的起点？
- [ ] sceneTransition 是否引用了上一场的具体内容？
- [ ] sceneTransition 是否说明本场的触发原因？
- [ ] sceneTransition 是否暗示了下一场的走向？

### 3.3 禁止的脱节模式

以下模式**严禁**出现：

1. ❌ **凭空换场景**：无过渡地从A地点跳到B地点
2. ❌ **凭空换人**：上一场角色A结束，下一场突然出现角色B且无引入
3. ❌ **凭空变状态**：角色状态突然改变且无交代
4. ❌ **跳章生成**：提前写下一章内容或回头改写已完成内容
5. ❌ **重复生成**：将同一段内容换措辞重复演绎
6. ❌ **角色漂移**：同一角色的外貌/性格/语言风格前后不一致

## 四、跨章节连贯性规则

### 4.1 章节开场规则

每章开头必须：

1. 明确交代本章的起始时间点
2. 展示上一章结尾主要角色的当前状态
3. 从上一章结尾的最后事件自然延伸
4. 禁止直接跳过时间而不做任何说明（如：直接"三天后"但不解释这三天发生了什么）

### 4.2 章节收尾规则

每章结尾必须：

1. 为所有出场角色记录状态账本
2. 明确本章留下的悬念/钩子
3. 为下一章设定清晰的起始点
4. 禁止突然中断正在进行的剧情线

### 4.3 跨章一致性检查

- [ ] 角色名是否与上一章一致？
- [ ] 角色外貌描述是否与上一章一致？
- [ ] 角色关系是否与上一章一致？
- [ ] 上一章的悬念是否在本章有推进？
- [ ] 上一章的角色状态是否自然延续到本章？
- [ ] 地点/时间线是否与上一章连贯？

## 五、AI生成强制指令

### 5.1 系统提示词强制注入

```
【全局锚点强制指令】
你必须严格遵循以下锚点规则进行剧本创作：

1. 角色锚点：
   - 只能使用【角色表】中已建立的角色
   - 角色名、外貌、性格、语言风格必须与角色表一致
   - 新角色出场必须在原文中有明确描述

2. 状态锚点：
   - 每个场景必须基于【角色状态账本】中记录的上一场状态
   - 角色的情绪、身体状况、位置、持有物品必须前后一致
   - 状态变化必须通过具体动作/对白体现，不得凭空改变

3. 场景锚点：
   - 每个场景的sceneTransition必须包含三个要素：
     a) 引用上一场的具体内容（动作/对白/情绪/事件）
     b) 说明本场如何因上一场触发
     c) 暗示下一场的走向

4. 禁止模式：
   - 禁止凭空换场景、换人、变状态
   - 禁止跳章生成、重复生成
   - 禁止角色漂移（外貌/性格/语言风格不一致）
```

### 5.2 上下文注入格式

```
【角色表】（全局锚点）
{canonical_characters_json}

【世界观锚点】
{world_context_json}

【角色状态账本】（上一章结尾状态）
{character_state_ledger_json}

【上一章剧本摘要】
{previous_chapter_summary}

【当前章节正文】
{current_chapter_content}

【生成指令】
请严格基于以上锚点，将当前章节正文转化为剧本场景。
每个场景必须承接上一场的角色状态，并在结尾为下一场留下明确的起点。
```

## 六、质检规则

### 6.1 连贯性质检项

1. **角色一致性检查**
   - 角色名是否与角色表一致
   - 角色外貌/性格描述是否前后一致
   - 角色语言风格是否符合人设

2. **状态连贯性检查**
   - 场景间角色状态是否连续
   - 状态变化是否有明确触发事件
   - 禁止凭空改变角色状态

3. **场景衔接检查**
   - sceneTransition是否包含三要素
   - 场景是否从上个场景自然过渡
   - 地点转换是否有合理说明

4. **章节连贯检查**
   - 本章开头是否承接上一章结尾
   - 本章结尾是否为下一章铺垫
   - 跨章角色状态是否一致

### 6.2 质检结果处理

- **严重脱节**（如凭空换人/换场景）：必须整章重写
- **中度问题**（如状态变化无说明）：标记问题，要求修正
- **轻微问题**（如sceneTransition不够具体）：标记警告，建议改进

## 七、输出格式规范

### 7.1 场景结构（含锚点标注）

```json
{
  "scenes": [
    {
      "sceneIndex": 1,
      "sceneTitle": "内景-咖啡馆-下午",
      "description": "详细场景描述...",
      "actions": "角色动作...",
      "dialogues": [
        {"character": "李明", "line": "台词内容"}
      ],
      "stageDirections": "镜头指示",
      "sourceBeat": "剧情段1",
      "sceneTransition": {
        "fromPrevious": "上一场李明在公司被老板训斥",
        "trigger": "李明心情低落，来到咖啡馆放松",
        "toNext": "李明在咖啡馆遇到老同学，下一场展开对话"
      }
    }
  ]
}
```

### 7.2 sceneTransition结构化

sceneTransition必须是包含三个关键字段的结构化对象（或等效的文字描述）：
- `fromPrevious`：引用上一场的具体内容
- `trigger`：说明本场的触发原因
- `toNext`：暗示下一场的走向

## 八、自我检查清单

在提交剧本前，请逐项检查：

- [ ] 所有角色是否来自角色表？
- [ ] 角色状态是否前后连贯？
- [ ] 每个场景的sceneTransition是否包含三要素？
- [ ] 是否存在凭空换场景/换人/变状态？
- [ ] 章节间是否自然衔接？
- [ ] 剧情是否完整覆盖当前章节正文？
- [ ] 是否有重复生成的内容？
- [ ] 人物性格、语言风格是否一致？
- [ ] 时间线是否线性推进？
- [ ] 地点转换是否有合理说明？

## 九、禁止输出内容

以下内容严禁出现在输出中：

- 角色状态账本的内部JSON结构
- 全局锚点的元信息
- 质检清单本身
- 任何内部注释或思考过程
- 与剧本无关的结构化数据标记
