# 创世纪 · 短剧开发读本与改编诊断

本技能服务于**短剧工作台前置开发层**：在正式进入「剧本格式化 → 角色场景提取 → 分镜拆解 → 配音/视频」前，先判断叙事文本是否值得改、怎么改、哪些东西必须被保住。

它不是正式剧本化，也不是剧情复述；它的任务是把小说、粗稿、大纲、长会话或剧本初稿转成可执行的短剧开发判断。

## 流水线位置

| 方向 | 说明 |
|------|------|
| **上游** | 小说片段、粗稿、剧情大纲、剧本初稿、长会话记录、互动叙事文本 |
| **本步产出** | 开发诊断、改编入口、保留/删并/扩写清单、演员/导演/编剧摘要、AI 剧本化提示包 |
| **下游** | `drama_script_formatter`、`drama_cast_scene_extract`、`drama_storyboard_breakdown`、`drama_voice_assign` |

## 最高原则

1. **先诊断，再开发**：先判断文本是否具备人物、冲突、场景、动作链、物件链和关系转折，再决定进入哪一步。
2. **证据分层**：区分原文事实、基于原文的强推断、短剧化建议；不要把推断写成原文事实。
3. **不急着重写**：本技能只给开发路径和执行约束，不直接替代 `drama_script_formatter` 写正式剧本。
4. **抓可拍骨架**：优先识别物件链、动作链、空间链、台词潜台词、沉默/停顿、关系转折。
5. **短剧优先**：所有判断要落回竖屏短剧的节奏、场景密度、角色辨识度和生成链路。

## 快速诊断等级

| 等级 | 判断 | 下一步 |
|------|------|------|
| A | 人物、冲突、场景和终局基本成立，可直接开发 | 输出完整开发摘要，推荐进入剧本格式化 |
| B | 故事核心成立，但人物/结构/场景有明显短板 | 先做编剧改编摘要或角色补强，再格式化 |
| C | 有设定或情绪，但开发入口未定 | 先判断单主角/双主角/群像/命题/设定入口 |
| D | 只有概念、氛围或碎片，暂不适合直接剧本化 | 输出最小重构建议 |
| D0 | 不具备开发基础或无法形成故事 | 终止开发，不进入下游 |

## 标准工作流

1. 读取原文，提取主要人物、关键场景、关键动作、关键物件、关系转折和终局。
2. 做快速诊断，给出 A/B/C/D/D0 等级。
3. 判断改编入口：
   - 单主角切入
   - 双主角切入
   - 群像切入
   - 命题切入
   - 行业切入
   - 设定切入
4. 判断短剧形态：
   - 单集短剧片段
   - 1–3 分钟竖屏短剧
   - 多集连续短剧
   - 单元短剧
   - 不建议短剧化
5. 输出保留/删并/扩写清单。
6. 按需要输出演员、导演、编剧或 AI 剧本化摘要。
7. 将下游执行约束交给对应 Skill，不在本步直接落库。

## 输出契约

正式输出建议包含以下部分：

### 1. 一句话开发判断

用一句话说明这个故事最值得保住的东西，以及是否适合短剧化。

### 2. 快速诊断

- 诊断等级：A/B/C/D/D0
- 核心成立点
- 当前最大短板
- 最强人物/关系/物件/场景
- 最危险的误开发方式

### 3. 改编入口判断

说明最适合从哪条线切入，并说明为什么不优先从其他线切入。

### 4. 必须保留 / 可删可并 / 必须扩写成戏

| 类型 | 内容 | 理由 |
|------|------|------|
| 必须保留 | 结构性场景、物件、台词、关系节点 | 删掉会导致故事降级 |
| 可删可并 | 重复日常、重复配角、纯说明段 | 可压缩到其他场景 |
| 必须扩写成戏 | 前情概述、关系转折、设定说明 | 需要动作、对白、场景承载 |

### 5. 内心独白转译方案

把抽象心理转成可拍材料：

- 动作：手部动作、停顿、回避、重复行为
- 场景：冲突发生的具体地点
- 物件：被拿起、放下、磨损、丢失、回收的东西
- 空间：靠近、隔开、进门、离开、占据或退回
- 旁白：仅在动作无法承载时少量保留

### 6. 演员读本摘要

只给后续角色提取/表演方向需要的信息：

- 角色核心命题
- 最不想被看见的脆弱点
- 防御方式
- 说话节奏与语言禁区
- 外在行为习惯
- 一句话表演方向

### 7. 导演视听摘要

只给后续分镜/视频导演需要的信息：

- 视觉母题：光、颜色、门窗、水、反射、身体、关键物件
- 声音母题：呼吸、停顿、环境声、重复声、沉默
- 关系空间：哪些空间承载人物关系
- 哪些交给镜头，不交给对白
- 哪些交给声音，不交给剧情解释
- 一句话导演提醒

### 8. AI 剧本化提示包

给 `drama_script_formatter` 的主控约束：

- 输入优先级
- 不可改项
- 可合并项
- 必须扩写项
- 角色口吻规则
- 场景/物件/空间约束
- 禁止误改方向

## 场景保留评分

判断场景是否保留时使用 3 条标准：

| 标准 | 说明 |
|------|------|
| 结构性承载 | 承载关键物件、关系转折或人物弧线 |
| 因果必要性 | 删除后会导致后续情节失去因果支撑 |
| 不可替代性 | 有不可替代的台词、动作、时空交汇或物件回收 |

命中 2 条以上：保留。  
命中 1 条：可压缩/可合并。  
命中 0 条：建议删除或并入其他场景。

## 输出前自检清单

- [ ] 没有把读本写成剧情复述
- [ ] 每个关键判断都有原文证据或明确标注为建议
- [ ] 已给出 A/B/C/D/D0 诊断等级
- [ ] 已判断改编入口和短剧形态
- [ ] 已列出必须保留、可删可并、必须扩写成戏
- [ ] 已指出最危险误改方式
- [ ] 已给下游 `drama_script_formatter` 可执行约束
- [ ] 没有直接调用下游落库工具

## 反例（不要这样做）

| 反例 | 问题 | 改法 |
|------|------|------|
| 只复述一遍剧情 | 对开发无帮助 | 输出诊断、保留/删并/扩写和误改风险 |
| 直接改成完整剧本 | 越过前置职责 | 把正式改写交给 `drama_script_formatter` |
| “这很适合影视化”但不说怎么转 | 判断空泛 | 指出动作、物件、空间、声音和场景转译 |
| 给角色乱补童年创伤 | 编造原文事实 | 只基于行为、台词、选择做强推断 |
| 一口气建议所有模块 | 失去优先级 | 按诊断等级推荐下一步最小动作 |
